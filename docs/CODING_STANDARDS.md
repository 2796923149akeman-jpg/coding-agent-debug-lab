# 代码规范与可重复检查

本仓库用于程序设计实操。规范既包括文件组织和代码可读性，也包括正确处理异常、保留输入、明确验收边界，以及记录真实运行结果。

## 代码与文件约定

- Python 使用 UTF-8、LF 换行、4 空格缩进，代码行长上限为 79；编辑器配置见 `.editorconfig`。
- 模块、函数和变量使用有意义的 `snake_case`，类名使用 `CapWords`，常量使用大写。
- 标准库、第三方库与本地模块分组导入，不保留未使用的导入。
- 配套工具的公共函数说明用途、输入和返回行为；注释解释必要的约束，不重复代码字面意思。
- 路径使用 `pathlib`，使用上下文管理器关闭文件；计算文件哈希时分块读取。
- 异常明确报错，不能静默丢文件；图片解码只捕获相关异常，不将任意编程异常都当成坏图片。
- 初始化不覆盖已有输入，整理代码应保留全部副本；每轮结果和报告分开保存。
- 依赖写在 `requirements.txt`，格式检查依赖写在根目录的 `requirements-dev.txt`，不在代码内自动安装。

这些约定参考 [PEP 8](https://peps.python.org/pep-0008/) 和 [PEP 257](https://peps.python.org/pep-0257/)，由 `pyproject.toml` 固定静态检查规则。它们是本仓库的约定，不代表替代课程自己的评分细则。

## 两类检查，不能混淆

**学生答案验收：** 成绩修复后三个测试必须通过；照片整理完成后运行自检、输入核对，再检查清单与日期。详见各案例 README。

**仓库材料自检：** 分发前要确认成绩案例仍带有预设错误、素材未变化、配套工具正常。这里成绩测试恰好两项报错是预期起点，不能当作工具代码质量检查失败，也不能把所有失败都忽略。

在仓库根目录执行：

```sh
python -m pip install -r labs/02-photo-organizer/requirements.txt
python scripts/check_repository.py
```

该命令检查成绩案例来源哈希、205 个素材字节、Python 3.10 语法、文档本地链接、成绩预设失败和照片工具回归测试。任何检查不符合预期，都返回非零状态。

这条命令用于尚未解题的材料副本。你修复成绩程序后，来源哈希检查会提示练习起点已变化；此时应使用该案例的学生验收命令，不要为了通过材料自检而撤销正确修复。

## 格式与静态检查（可选）

在仓库根目录执行：

```sh
python -m pip install -r requirements-dev.txt
python -m ruff check .
python -m ruff format --check .
```

检查覆盖常见语法、导入、格式和潜在错误，不等于证明所有业务逻辑正确。成绩案例的源程序和测试保留分发时的字节与来源记录，参与静态检查，但不由格式化工具自动重排；配套工具和仓库检查脚本统一格式化。

## 环境与验证范围

代码以 Python 3.10 语法为目标；本次实际运行环境为 Windows、Python 3.13.9、Pillow 12.0.0，静态检查为 Ruff 0.12.0。语法兼容检查不等于所有 Python 版本和操作系统都已实测。

如需复现这次照片工具的依赖版本，可在独立环境中安装 `Pillow==12.0.0`。日常安装范围以案例的依赖文件为准，换版本后应重新运行回归测试。

学生自检不判断完整的日期语义、近重复质量或报告完整性；这些仍需按验收说明检查。缺少依赖时，应先按安装说明配置环境，再解释程序的退出状态。
