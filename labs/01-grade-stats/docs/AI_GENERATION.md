# 这个案例如何由 AI 辅助生成

## 可以确认的来源与边界

这份练习整理自已有的《Coding Agents 两人汇报材料包》中的 `demo/coding-agent-demo`。本次发布保留了其中的 `grade_stats.py`、`test_grade_stats.py` 和 `data/scores.csv`，可用本案例目录中的 `provenance.json` 的 SHA-256 核对。

原材料明确将它设计为一个“故意保留错误”的课堂案例：初始一项测试通过、两项报错，另有备用正确版本。它不是对真实软件事故的记录，也不是 AI 在实际业务中偶然写错代码的证据。

本次整理由 AI 完成了面向学生的 README、提示词、练习记录、生成流程说明和发布前验证。现有材料没有提供最初生成代码的完整对话、精确模型版本或逐步时间记录，因此无法据此独立还原最初生成过程。下面的提示词是依据已有项目重新整理的**复现提示词**，不是原始对话的逐字引用。不要将本次整理日期当成原案例创建日期。

## 教学案例的设计流程

1. 人先确定教学目标：让同学看懂“读项目 → 运行 → 报错 → 修复 → 复测 → 人工验收”。
2. 选择结果可以手算的小业务：读取 CSV 成绩，跳过空白并统计未填写人数。
3. 将业务规则写成三个测试：正常数据、混有空白、全部空白。
4. 让 AI 生成两个独立版本：带有指定缺陷的学生版，以及供汇报者验证的正确参考版。
5. 实际运行两版，确认初始稳定报错、参考版通过；再手算 80、空白、90 的结果。
6. 只向练习仓库提供带故障的学生版，让同学自己的 AI 完成修复。参考答案应放在练习工作区外，避免 AI 直接复制答案。

上述步骤说明如何制作和复现这种案例，不表示已经找回原作者每一步的操作记录。

## 可复制的生成提示词

在另一个空目录 / 新对话中使用，避免覆盖当前练习：

```text
请帮我生成一个用于课堂演示 Coding Agent 纠错流程的最小 Python 项目。
教学目标：让初学者观察阅读项目、运行测试、定位故障、修改、复测和人工验收。

业务要求：
1. 从 CSV 读取 name 和 score 两列。
2. 空白或纯空格的 score 计入 missing，不参与平均分。
3. 有效成绩取平均值并保留两位小数；全部空白时 average=None。
4. summarize_scores(csv_path) 返回 {"average": ..., "missing": ...}。
5. 命令行可以读取 data/scores.csv，并以中文输出结果。

交付两个互相独立的文件夹 student 和 instructor，不要让学生版导入或读取参考版。
两版各有 grade_stats.py、test_grade_stats.py、data/scores.csv、README.md。
测试仅用 unittest，恰好三个：全有成绩、混有空白、全部空白（包含纯空格）。
示例数据为 80、空白、90，名字使用虚构代称。

student 故意不处理空白、直接转为 float，且不处理无有效成绩时的平均值。
不要在学生源码注释里写出答案。
instructor 是正确实现；两版测试文件内容完全一致。
不使用第三方依赖，不用真实个人数据，不需要联网或 API Key。

请实际验证：学生版 3 项测试中 1 项通过、2 项报错；参考版 3 项全通过；
参考版示例平均分 85.0、未填写 1 人。
提供实际命令与输出；若没有执行能力，明确说明并提供人工验证步骤。
不要声称未执行的命令已经成功。不要修改测试预期来制造通过。
```

不同模型可能生成不同代码结构；复现目标是同样的需求、故障类型和验收结果，不是保证每个字符都一致。若需要完全相同的课堂起点，请从仓库 README 下载当前实操包，使用其中的 `labs/01-grade-stats`。

## 验证 AI 生成的案例

分别在两个文件夹运行 `python -m unittest -v`；仅在参考版运行示例，检查 `85.0` 和 `1`。比较两版测试文件，确保它们一致。还应确认参考版没有针对固定数据硬编码结果。

出题阶段的 AI 可以辅助写需求、程序与测试，验收仍需要人检查业务含义。例如把空白改成零分虽然可能不报错，却不符合本练习的平均分规则。编写测试和修复代码若都依赖同一模型，可能共享盲点，所以要保留独立手算和边界检查。

## 汇报时可以怎么说

> 我们使用了一个 AI 辅助准备的教学案例，需求是统计成绩平均值和未填写人数，学生版有意保留了空白成绩处理问题。大家下载后，可以让自己的 AI 复现报错、修复并重新测试。仓库还提供了同类案例的生成提示词，这是根据现有项目整理的复现版本，不是最初对话原文。验收既看真实测试输出，也看人工手算是否一致。
