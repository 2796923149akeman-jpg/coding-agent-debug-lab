# 两人课堂汇报：两个案例都现场演示

本次课堂依次演示成绩统计纠错和照片整理。第一位同学负责概念介绍与观察提示，第二位同学负责两个案例的现场操作与讲解。两人共同完成最后的结果复核与总结。

## 45 分钟安排

| 时间 | 负责人 | 课堂内容 |
| --- | --- | --- |
| 0～10 分钟 | 介绍同学 | 定义、工具与反馈循环，说明人如何给目标和验收标准 |
| 10～12 分钟 | 介绍同学 | 展示仓库下载与目录，说明接下来两个案例的任务 |
| 12～22 分钟 | 演示同学 | 成绩统计：阅读 → 两项报错 → 修复 → 三项通过 → 手算解释 |
| 22～39 分钟 | 演示同学 | 照片整理：观察 205 个文件 → 编写 → 运行 → 自检 → 改进 → 人工复核 |
| 39～45 分钟 | 两人 | 对照两次过程解释 Coding Agent，查看证据并回答问题 |

课堂演示覆盖两个案例。同学可同步跟做；独立练习速度不必与讲台一致。成绩案例通常预留 15～20 分钟、照片案例预留 30～50 分钟完成个人操作，未完成的步骤可以继续练习。

## 课前准备

1. 从仓库下载当前实操包，按 [上手指南](GETTING_STARTED.md) 确认两套目录。
2. 在成绩案例目录运行初始测试，确认一项通过、两项报错。
3. 在照片案例目录安装依赖，运行 `prepare.py`，确认输入为 205 个文件。
4. 两个案例分别彩排；正式演示使用新的练习副本和对话，保持课堂起点一致。
5. 打开两个案例的分步提示词，准备记录终端输出和代码差异。

若时间或网络影响现场生成，可以使用提前彩排的代码和日志辅助解释，但要清楚标注“彩排结果”，不要说成现场刚执行。照片案例仍要展示任务、结果与验收过程。

## 交接与第一段演示

介绍同学：“下面连续看两个任务。先让 Agent 修复已有程序，再让它根据需求完成一个文件整理任务。请一直观察它读取了什么、调用了什么工具、根据什么结果继续修改。”

演示同学按 [成绩提示词](../labs/01-grade-stats/docs/STUDENT_PROMPTS.md) 操作。运行前先说明预期，运行后展示实际结果。不要省略初始报错，也不要只展示最后代码。

观众应能回答：为什么要先测试？空白为什么不能当零分？同样三项测试从报错变为通过说明了什么，又不能证明什么？

## 从成绩案例过渡到照片案例

“成绩案例已有程序和三个测试，我们主要观察如何修复。接下来整理 205 个混杂文件，Agent 需要先理解需求和数据，再编写程序。这里要特别注意：代码跑完不等于任务完成，所以还需要自检、清单和人工判断。”

## 第二段演示

1. 展示 `input/` 和任务目标：按年月归档、文件不丢、不能覆盖、每个去向可追溯。
2. 让 Agent 观察输入并提出方案，展示实际读取或检查数据的证据。
3. 让它创建 `organize.py`，按约定接口执行，不提前将参考实现放进工作区。
4. 运行 `self_check.py` 和输入核对；出现失败时，让 Agent 依据输出解释并修改，再用新结果目录复测。
5. 展示清单、月份目录和重复报告，解释自检未覆盖的部分。

若第一版就通过，不需要人为制造报错；继续抽查清单与日期，说明为什么通过自检仍需验收。若未通过，失败本身就是讲解材料，必须如实说明仍未完成的部分。

验收目标和教师检查方式见 [照片结果说明](../labs/02-photo-organizer/EXPECTED_RESULTS.md)。

## 最后的理解检查

请同学对照 [理解 Coding Agent](UNDERSTANDING_AGENTS.md)，各从两段演示中举出一次“工具调用”和一次“运行反馈影响下一步”的例子。

最后强调：人给目标、约束和验收；Agent 在授权范围内执行并迭代；真实输出与人工复核共同支撑结论。让同学按 [记录模板](EXPERIMENT_REPORT.md) 保留两段实操证据。
