# 用两个实操案例理解 Coding Agent

## 先观察六个动作

| 动作 | 成绩统计中看到什么 | 照片整理中看到什么 |
| --- | --- | --- |
| 理解目标 | 跳过空白成绩，计算平均分和未填写人数 | 按年月归档，保留 205 个文件，输出可追溯清单 |
| 收集上下文 | 阅读程序、测试和 CSV | 阅读任务，观察文件和元数据 |
| 选择行动 | 先运行测试，再定位问题 | 先检查数据，再设计并编写整理脚本 |
| 使用工具 | 终端运行测试，编辑程序文件 | 运行检查脚本、创建代码、复制归档文件 |
| 根据反馈调整 | 用报错和复测结果决定下一步 | 用数量、哈希、解码等检查发现遗漏并迭代 |
| 验收与交付 | 三项测试通过，人工手算样例 | 自检、输入核对、清单与日期抽查共同验证 |

Coding Agent 将这些动作连接成一个循环。它可能一次完成，也可能需要多轮；实际步骤和结果取决于模型、工具权限、项目情况和任务表达。

## 聊天写代码与 Agent 操作有什么区别

普通对话中，你把问题发给 AI，它给出建议或代码；文件保存、运行和反馈可能主要由你搬运。能够操作项目的 Agent 可以在授权工作区中完成读取、编辑和执行，再依据终端输出继续工作。

二者都可以参与本次练习。判断当前是否形成 Agent 工作循环，应看实际发生了什么，而不能只看产品名称或回答语气：有没有读真实文件？有没有执行工具？有没有根据真实结果继续调整？

## 第一个案例为什么从失败开始

成绩程序在空白输入上报错。先运行测试留下失败证据，能确认问题确实存在，也能比较修改前后表现。修复后继续用相同的测试，避免把“改了程序”误当成“解决了问题”。

人的任务是解释业务：空白不应算零分，全部空白时也不应返回一个假平均值。测试通过后，用 80、空白、90 的例子手算检查，才把代码行为与业务要求连接起来。

## 第二个案例为什么还要自检和人工检查

照片整理包含不同文件类型、日期来源和重复情况。程序可能运行结束，却静默跳过文件，或把所有内容归到错误月份。

因此需要多种证据：数量与内容副本数检查是否丢失，输入核对检查是否改坏素材，逐文件清单解释去向，日期抽查判断业务含义。近重复候选还需要人观察，不能仅因相似度接近就自动删除。

学生自检只覆盖部分指标。将所有文件直接复制到一个文件夹也可能通过其中的检查，却没有完成按年月整理的任务。验收标准应先由人明确，不能由 Agent 随意降低。

## “自己纠错”具体指什么

本练习中，Agent 根据报错和检查结果修改的是项目文件、代码和执行方案。这个过程不等于在现场重新训练模型，也不意味着它会永久记住这次练习。

报错并不自动带来正确修复。它仍可能误判、反复修改，或遗漏测试之外的情况，所以要保留过程证据，让人能够检查。

## 人和 Agent 各负责什么

人提出目标、约束和验收标准，决定访问范围，并判断结果是否符合实际需要。Agent 在这些约束内收集信息、编写或修改程序、执行工具、整理证据和建议。

如果没有终端权限，Agent 应说明不能执行；如果日期来源不可信，应明确标注；如果近重复难以判断，应给候选与依据。把不确定的内容说清楚，也是可用结果的一部分。

## 练习完成后的自问

1. 两个案例中，哪些信息来自文件或终端，哪些只是 AI 的推断？
2. 哪次修改是由真实失败推动的？修改后用了什么证据验证？
3. 如果 AI 删除测试或改自检来“通过”，为什么仍然没有完成任务？
4. 如果所有自动检查都通过，还有哪些要求需要人确认？
