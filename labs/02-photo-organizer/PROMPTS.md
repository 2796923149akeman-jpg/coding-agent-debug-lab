# 照片整理：分步发给 AI

先在当前案例目录执行 `python prepare.py`。Agent 工作区只打开本案例目录。普通聊天 AI 无法读取本地文件时，由你执行它给出的脚本，把真实输出传回去；不要一次向聊天窗口粘贴全部二进制素材。

## 1. 观察与计划

```text
请阅读 README.md，并观察 input 中的真实文件；先不写整理程序。
说明任务验收标准、文件类型及可能的异常，列出你实际观察到的证据。
不要读取参考答案，不修改输入文件、prepare.py、self_check.py、data 下的素材或测试。
如果不能访问文件或运行命令，请说明限制，让我运行检查脚本并回传真实结果。
```

## 2. 编写第一版

```text
请创建 organize.py，接口为 python organize.py input output reports。
按 README 的规则整理这 205 个文件，保留所有原始副本，不更改 input，不覆盖现有输出。
为每个文件记录来源、去向、分类和日期来源；报告放 reports，不放 output。
时间戳按 UTC+08:00 解释。无法确认的内容明确标注，不要猜测后装作确定。
先实现可运行的第一版，再实际运行。不能执行时，让我运行并提供输出。
```

## 3. 自检和迭代

```text
请运行 python self_check.py input output 和 python prepare.py --check。
报告真实输出和退出码，逐项解释失败原因。只修改 organize.py，不能修改素材、自检、测试或验收标准来制造通过。
再次运行时不要删除旧结果，请将上一轮结果保留在独立目录，使用新的输出目录复测。
```

## 4. 人工验收

```text
请核对每个输入文件都有可追溯去向，总数与每种内容的副本数一致。
抽查不同日期来源的月份是否合理，说明是否存在不可信的日期。
解释完全重复与近重复的区别，近重复只列候选，不自动删除。
展示代码差异和运行证据，并指出学生自检覆盖不到的部分。
```

完成后可增加增量整理、近重复候选人工确认、日期置信度等扩展。先保留基础版和运行记录，每次扩展单独验证。
