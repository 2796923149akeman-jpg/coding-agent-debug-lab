# 这个案例如何由 AI 辅助生成

## 练习设计与生成说明

本案例的程序、测试与示例数据可用案例目录中的 `provenance.json` 核对来源和完整性。程序有意保留空白成绩处理问题：初始一项测试通过、两项报错。它不代表真实软件事故，也不能用于证明 AI 在实际业务中偶然写错代码。

本仓库的练习说明与验证流程由 AI 辅助整理。完整的最初生成对话和精确模型版本未随材料提供，下面的提示词是依据项目整理的复现版本，不是原始对话逐字引用。

## 教学案例的设计流程

1. 人先确定教学目标：让同学看懂“读项目 → 运行 → 报错 → 修复 → 复测 → 人工验收”。
2. 选择结果可以手算的小业务：读取 CSV 成绩，跳过空白并统计未填写人数。
3. 将业务规则写成三个测试：正常数据、混有空白、全部空白。
4. 让 AI 生成两个独立版本：带有指定缺陷的学生版，以及用于独立验证的正确参考版。
5. 实际运行两版，确认初始稳定报错、参考版通过；再手算 80、空白、90 的结果。
6. 只向练习仓库提供带故障的学生版，让同学自己的 AI 完成修复。参考答案应放在练习工作区外，避免 AI 直接复制答案。

上述步骤说明如何制作和复现这种案例，不表示已经找回原作者每一步的操作记录。

教学目标：让初学者观察阅读项目、运行测试、定位故障、修改、复测和人工验收。

业务要求：
1. 从 CSV 读取 name 和 score 两列。
2. 空白或纯空格的 score 计入 missing，不参与平均分。

5. 命令行可以读取 data/scores.csv，并以中文输出结果。

交付两个互相独立的文件夹 student 和 instructor，不要让学生版导入或读取参考版。
两版各有 grade_stats.py、test_grade_stats.py、data/scores.csv、README.md。
测试仅用 unittest，恰好三个：全有成绩、混有空白、全部空白（包含纯空格）。

student 故意不处理空白、直接转为 float，且不处理无有效成绩时的平均值。
不要在学生源码注释里写出答案。

不同模型可能生成不同代码结构；复现目标是同样的需求、故障类型和验收结果，不是保证每个字符都一致。若需要完全相同的练习起点，请从仓库 README 下载当前实操包，使用其中的 `labs/01-grade-stats`。

## 验证 AI 生成的案例

分别在两个文件夹运行 `python -m unittest -v`；仅在参考版运行示例，检查 `85.0` 和 `1`。比较两版测试文件，确保它们一致。还应确认参考版没有针对固定数据硬编码结果。

出题阶段的 AI 可以辅助写需求、程序与测试，验收仍需要人检查业务含义。例如把空白改成零分虽然可能不报错，却不符合本练习的平均分规则。编写测试和修复代码若都依赖同一模型，可能共享盲点，所以要保留独立手算和边界检查。
